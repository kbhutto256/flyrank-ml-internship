FlyRank Search Intelligence Capstone · Refresh / Content Opportunity Scoring

When a Better Split Beats a Better Model

A leakage-aware study of page-decline triage on real FlyRank search data, and why client-grouped validation changed the conclusion from “promising model” to “use a cautious review playbook.”

Abstract

FlyRank's Refresh / Content Opportunity Scoring lane starts with a practical content problem: when a team has more pages than it can manually inspect, which pages should be reviewed first after changes in search visibility? I built a March 2026 content-level modeling frame from the FlyRank internship warehouse using five Google Search Console signals observed before a fixed decision point, then compared a transparent rule baseline with Logistic Regression. A naive random-row split made the learned model look substantially stronger, with Precision@50 of 0.620, but client-grouped validation fell to 0.340 against a 0.373 held-out base rate. On the Week-5 grouped split, the transparent rule baseline also beat Logistic Regression on the primary ranking metric, 0.540 versus 0.380. The result is therefore not a model-win story: stricter validation changed the recommendation from “trust the model” to an explainable, human-reviewed FlyRank content-triage playbook.

Introduction / Problem statement

The real FlyRank content problem in this lane is prioritization under limited editorial capacity. Search-performance data can surface many pages with weak CTR, ranking depth, or declining visibility, but a content team cannot investigate every signal at once. This work asks whether pre-decision GSC signals can help rank the pages that deserve human review first while still holding up on clients the model did not see during training. A high score means “review sooner,” not “Google will demote this page,” and not “refreshing this page will recover traffic”; the intended output is a cautious triage queue that supports editorial judgment.

Data

The analysis uses the gated FlyRank internship warehouse and the fact_content_daily_performance table. Features use March 1–15, 2026 and the outcome uses March 16–31, 2026. The executed modeling frame contains 151,981 client-content rows across 44 clients. Only rows with gsc_data_available IS TRUE are used. Client/content IDs, second-half metrics, future-derived fields, private page information, and private query information are excluded from predictors and from this public artifact.

Methodology

The five features are first-half impressions, clicks, average position, active days, and CTR. The target is decline_proxy = 1 when second-half impressions are below 80% of first-half impressions. Logistic Regression is compared with a transparent training-only rule baseline. Precision@50 is the primary metric because the product is a ranked review queue. The decisive validation is client-grouped so no client appears in both training and test. All features end before the label window, raw identifiers are not predictors, and future-derived fields are excluded as leakage checks.

Limitations & honest framing

This is one March 2026 decision window in an unbalanced panel. The decline label is a proxy, not a causal diagnosis. Search movement can reflect seasonality, SERP changes, site changes, demand shifts, technical issues, or other unobserved factors. The learned model did not demonstrate useful grouped Precision@50 lift. This work is directional decision-support, not a claim about Google's ranking algorithm and not proof that refreshing content causes recovery.

Ranked recommendations

  1. Ranking-depth review: inspect high-impression pages with weak average position; check competing results, topical gaps, and internal links before rewriting.
  2. CTR review: inspect visible pages with weak CTR; check intent fit and SERP presentation.
  3. Refresh review only with supporting evidence: check staleness, factual drift, cannibalization, and usefulness; a refresh candidate is not proof of cause.
  4. Monitor low-evidence pages: defer edits when opportunity is small or signals are mixed.

On 13,210 held-out rows, the action layer assigned 12,755 to monitor/low-evidence, 285 to CTR opportunity, and 170 to ranking-depth opportunity.
